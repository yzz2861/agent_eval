# Sigma Rule Deployment Review Example

This scenario fills the highest-severity known detection blind spots with at most three
rule changes and four cost units of processing capacity.

The labelled corpus contains ten attack drills (`A0`-`A9`) and six benign normal-operation
drills (`B1`-`B6`). Two legacy rules establish the old true-positive hits that must survive
the change: `A1` (hidden encoded PowerShell) and `A4` (PowerShell download).

## Decision Inputs

- `P` is the common prerequisite for both PowerShell rewrites.
- `A` and `B` are the two mutually replacing variants in group `powershell-rewrite`.
  `A` covers the readable IEX cradle (`A2`); `B` covers unhidden encoded PowerShell (`A3`).
  Both retain `A1` and `A4`.
- `C` covers the certutil URL-cache download (`A5`) for one cost unit.
- `D` covers MSHTA remote HTA (`A6`) but cannot coexist with the retention-preserving
  PowerShell rewrite inside the capacity budget.
- `E` covers Regsvr32 Squiblydoo (`A7`) but only by displacing a higher-severity detection.
- `A8` and `A9` have no capable candidate and are explicit rule-capability gaps.

## Result

Two plans tie on severity coverage, cost, and rule count:

| Plan | Rules | Alert fingerprint |
|---|---|---|
| 1 | `P + A + C` | `A0,A1,A2,A4,A5` |
| 2 | `P + B + C` | `A0,A1,A3,A4,A5` |

Both retain `A1,A4`, produce zero benign alerts, and replay their alert rows from a fresh
`SigmaMatcher` invocation. `plans.json` stores the cached and replayed rows for both plans.

## Files

- `scenario.yml` — labelled cases, baseline, candidates, and constraints.
- `coverage_matrix.md` — rule-by-case matrix generated by the local matcher.
- `plans.json` — full machine-readable output including per-plan replay rows.
- `report.md` — deployment review with uncovered-case explanations.

Regenerate all artifacts from the repository root:

```bash
python -m sigma.matching.deployment examples/rule_deployment/scenario.yml \
  --coverage examples/rule_deployment/coverage_matrix.md \
  --json examples/rule_deployment/plans.json \
  --report examples/rule_deployment/report.md
```
