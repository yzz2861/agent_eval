# DUO139

This linter tracks one-time approval tickets through a release script. It
recognizes configurable issue, borrow, and consume APIs, follows tickets
through local aliases, simple containers, and a limited amount of helper-call
inlining, and reports a ticket that can be consumed more than once on a
reachable path.

The rule is path-sensitive: mutually exclusive branches that each consume a
ticket once are accepted. A retry loop, a compensation handler, or a fall-through
path that consumes the same ticket twice is reported at both call sites. When a
ticket comes from an external call whose return value cannot be analyzed, the
linter emits a separate unknown-status finding instead of guessing.

## Problematic code

```python
ticket = approvals.issue_approval()

try:
    approvals.consume_approval(ticket)
    raise ReleaseError("retry")
except ReleaseError:
    approvals.consume_approval(ticket)
```

## Correct code

Mutually exclusive branches each consume the ticket at most once:

```python
ticket = approvals.issue_approval()

if use_primary:
    approvals.consume_approval(ticket)
else:
    approvals.consume_approval(ticket)
```

Read-only borrow APIs do not spend the ticket:

```python
ticket = approvals.issue_approval()
approvals.peek_approval(ticket)
approvals.peek_approval(ticket)
approvals.consume_approval(ticket)
```

## Configuration

The linter can be configured through constructor keyword arguments or by
subclassing it. Lists may contain plain names such as "mint", dotted paths
such as "release.approvals.mint", or glob patterns such as
"release.approvals.*". A callable predicate receives the resolved dotted
callee path.

```python
from dlint.linters import ApprovalReuseLinter

linter = ApprovalReuseLinter(
    issuance_apis=["mint"],
    borrow_apis=["peek_ticket"],
    consumption_apis=["spend"],
)
```

Aliases for the same keyword arguments include issue_apis/consume_apis,
issuers/borrowers/consumers, and an apis or api_config mapping with issue,
borrow, and consume keys.

## Unknown status

```python
ticket = load_ticket_from_external_store()
approvals.consume_approval(ticket)
```

This produces a DUO139 approval status unknown finding because the external
return value cannot be tied to a known ticket identity.

## Exceptions

The analysis is intentionally limited to local aliases, literal or simple
container values, and helper calls that can be inlined within a small analysis
budget. It does not prove all program paths safe, and an unknown-status finding
should be reviewed manually.
