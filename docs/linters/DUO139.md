# DUO139

This linter looks for sensitive dictionary keys that can be removed and then
restored before a log record is submitted. The rule is intended for logging
adapters which merge project default context into the supplied dictionary.

Sensitive keys and the calls which actually submit log records are configured
by the project. For example, with Flake8:

```
[flake8]
dlint-sensitive-keys = password,token
dlint-log-calls = logging.info,logger.warning
```

A JSON file with `sensitive_keys` and `log_calls` lists can also be supplied
with `--dlint-config /path/to/config.json` or `DLINT_CONFIG`.

The rule follows aliases, dictionary copies, merges, and branches. It reports
the last operation which reintroduced the key, rather than the original
dictionary creation or an early redaction. Calls to adapters whose definition
cannot be resolved in the analyzed file are left for human review.

## Problematic code

```
payload = {"password": "secret", "message": "hello"}
payload.pop("password")
logger.info(payload)
```

The logging adapter merges its default context, so `password` can reappear in
the emitted record.

```
payload.pop("password")
payload.update(DEFAULT_CONTEXT)
logger.info(payload)
```

Here the merge at `update` restores the key and is the reported location.

## Correct code

Remove the key from the final dictionary which is submitted, after all merges:

```
payload.update(DEFAULT_CONTEXT)
payload.pop("password", None)
logger.info(payload)
```

Alternatively, pass an independent copy which was never populated with the
sensitive key.

## Exceptions

Calls which do not match the configured log calls are ignored. This keeps
unknown adapters out of the report so a reviewer can confirm their behavior.
