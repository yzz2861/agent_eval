# DUO139

This linter looks for classified sample data that can flow from a generator
into a debug exporter which is only allowed to receive public fields.

The check follows a deliberately small, explicit subset of Python:

* A value is classified when its name, annotation, constructor, or
  `classification`-style keyword marks it as classified, confidential, private,
  restricted, secret, or sensitive.
* A debug exporter is a call whose name contains both `debug` and an export
  verb such as `dump`, `emit`, `export`, `log`, `output`, `trace`, or `write`,
  or a call using a public-only keyword such as `public_only=True`.
* A public projection is a value whose name contains `public`, `redacted`, or
  `sanitized`. For example, `sample.public_fields` is treated as safe.

Generator outputs, delegated outputs, values supplied to `send`, and final
return values are tracked separately. In particular, `yield from child()` only
inherits values that `child()` yields. The child's return value is available as
the value of the `yield from` expression. A value assigned from `yield` is a
value sent into the generator, not a value produced by it.

## Problematic code

The same classified value is yielded and returned below. Iterating the
generator in the debug exporter exposes the yielded value; the return value is
not yielded by iteration.

```python
def debug_export(values):
    pass


def read_sample(classified_sample):
    yield classified_sample
    return classified_sample


def troubleshoot(classified_sample):
    debug_export(read_sample(classified_sample))
```

The diagnostic names the classified source and the actual crossing path. It
does not report the independent `return` path:

```
DUO139 classified data may reach a public-only debug export
(path: classified source "classified_sample" at 11:17; yield at 7:4)
```

Delegated generators have the same distinction:

```python
def child(classified_sample):
    yield classified_sample.public_fields
    return classified_sample


def parent(classified_sample):
    tail = yield from child(classified_sample)
    return tail
```

Here `parent` yields only public fields. The classified return value stays in
`tail`; it does not become an output unless `parent` explicitly yields it.

## Correct code

Project the original sample to public fields before yielding or returning it:

```python
def read_sample(classified_sample):
    yield classified_sample.public_fields
```

Values sent into a generator are inputs, so they are not reported merely
because `.send(classified_sample)` is called. They are reported if the
generator later yields or returns them.

## Rationale

Debug exporters often have weaker access controls than production export
paths. Passing a classified sample through a generator can obscure whether a
particular value was actually emitted, delegated from a child generator, sent
back into a suspended generator, or only returned when iteration completed.
Conflating these paths either hides a real disclosure or reports a value that
never reaches the exporter.

Unknown calls that receive classified data are kept conservative and their
call site is retained in the diagnostic path. This makes the uncertain
assumption visible instead of silently dropping the data flow.
