# DUO139

This linter flags calls to configured entry points that rely on an insecure
default value for a configured switch keyword argument.

Python captures default argument values when the `def` statement executes,
not when the function is called. A check that resolves a name to its most
recent assignment will miss wrappers whose default was frozen to an
insecure value before the name was rebound. This linter distinguishes
def-time ("frozen") defaults from configuration values supplied at the
call site. Keyword-only parameters, rebinding of switch names, and
forwarding calls between functions in the same module are all handled.
Source files are never executed; only statically resolvable literals are
considered.

## Configuration

The rule is controlled by three class attributes, which engineers set to
the few switches and entry points they care about (e.g. by subclassing):

* `switch_kwargs`: keyword argument names that act as security switches,
  e.g. `("verify",)`.
* `entry_points`: dotted paths of the functions whose calls should be
  checked, e.g. `("mymod.client.request",)`. A bare name such as
  `"request"` also matches attribute calls like `client.request`.
* `unsafe_values`: literal values considered insecure, e.g. `(False,)`.

With no configuration the linter reports nothing.

## Problematic code

```python
LEGACY_VERIFY = False

def request(url, verify=LEGACY_VERIFY):  # frozen to False at def time
    ...

LEGACY_VERIFY = True  # rebinding does NOT thaw the default above

request(url)  # still runs with verify=False
```

```python
def request(url, *, verify=False):  # keyword-only switches are handled
    ...

def fetch(url):
    return request(url)  # forwarding call relies on the frozen default
```

## Correct code

```python
def request(url, verify=True):
    ...

request(url)
request(url, verify=True)  # an explicit safe value overrides the default
```

## Unknown provenance

A call is only reported when its effective switch value provably equals
one of the unsafe values. Calls whose value cannot be determined
statically remain unknown and are not reported:

```python
request(url, verify=get_config())  # call result: unknown
request(url, **settings)           # '**kwargs' forwarding: unknown

def fetch(url, verify):            # parameter without a default: unknown
    return request(url, verify=verify)
```

## Rationale

Disabling a legacy compatibility switch at the top of a module does not
change defaults that were already captured by earlier `def` statements.
Wrapper functions can therefore silently keep the old insecure behavior
even after the switch is flipped, and every forwarding call site
propagates it.
