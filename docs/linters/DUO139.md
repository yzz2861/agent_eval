# DUO139

This linter searches for integrity checks that compare digests produced from
different source objects. A common mistake in file receiving services is to
hash the download URL and then submit that value as if it were the digest of
the received file content.

The rule only analyzes source code that is present in the linted file. It does
not assume the behavior of third-party hash implementations. Instead, it
follows simple assignments, closures, and local function parameter bindings to
determine which source object each digest was computed from.

## Configuration

The linter is project-aware. Configure the parameters that represent the
original artifact and the final comparison points that claim to verify
integrity:

```python
from dlint.linters import DigestSourceMismatchLinter

linter = DigestSourceMismatchLinter(
    original_parameters={"content", "body"},
    integrity_comparison_points={
        "hmac.compare_digest",
        "verify_digest",
    },
)
```

The same configuration can be applied with class attributes:

```python
class FileReceiverDigestLinter(DigestSourceMismatchLinter):
    original_parameters = {"content", "body"}
    integrity_comparison_points = {"hmac.compare_digest", "verify_digest"}
```

## Problematic code

Both parameters below are `bytes`, so a type-based check cannot tell them
apart. The object provenance still shows that the left digest came from the
download URL while the right digest came from the original content:

```python
import hashlib
import hmac


def receive_file(download_url: bytes, content: bytes) -> bool:
    url_digest = hashlib.sha256(download_url).hexdigest()
    content_digest = hashlib.sha256(content).hexdigest()
    return hmac.compare_digest(content_digest, url_digest)
```

The rule also follows aliases, hash builders, closures, and parameter
bindings:

```python
def make_checker(expected):
    def check(actual):
        return hmac.compare_digest(expected, actual)
    return check


def receive_file(download_url: bytes, content: bytes) -> bool:
    content_digest = hashlib.sha256(content).hexdigest()
    url_digest = hashlib.sha256(download_url).hexdigest()
    checker = make_checker(content_digest)
    return checker(url_digest)
```

## Correct code

Compute both values from the same object, for example by hashing the downloaded
content again rather than the URL that the content came from:

```python
def receive_file(download_url: bytes, content: bytes) -> bool:
    expected_digest = hashlib.sha256(content).hexdigest()
    actual_digest = hashlib.sha256(content).hexdigest()
    return hmac.compare_digest(expected_digest, actual_digest)
```

## Exceptions

Digests used only as cache keys, dictionary keys, or deduplication
fingerprints are allowed. The rule reports only when a digest reaches a
configured integrity comparison point:

```python
def receive_file(download_url: bytes, content: bytes) -> None:
    cache = {}
    seen = set()

    cache[hashlib.sha256(download_url).hexdigest()] = content
    seen.add(hashlib.sha256(content).hexdigest())
```

## Rationale

An integrity check is only meaningful when both sides describe the same
object. Comparing a URL digest against a content digest can accept a value
that was never derived from the received bytes. Because both values are often
typed as `bytes`, the mismatch must be found through object provenance rather
than the static type.
