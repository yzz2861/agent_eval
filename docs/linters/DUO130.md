# DUO130

This linter searches for insecure use of the `hashlib` module.

More specifically this searches for MD5 or SHA1 use when hashing. Both of these
hashing algorithms are considered insecure at this point:

* [Is MD5 considered insecure?](https://security.stackexchange.com/questions/19906/is-md5-considered-insecure)
* [How secure is SHA1? What are the chances of a real exploit?](https://crypto.stackexchange.com/questions/48289/how-secure-is-sha1-what-are-the-chances-of-a-real-exploit)

## Problematic code

```python
import hashlib

md5_hashed = hashlib.md5(b"data").hexdigest()
sha1_hashed = hashlib.sha1(b"data").hexdigest()
```

## Correct code

```python
import hashlib

sha256_hashed = hashlib.sha256(b"data").hexdigest()
sha512_hashed = hashlib.sha512(b"data").hexdigest()
blake2b_hashed = hashlib.blake2b(b"data").hexdigest()
# ...
```

## Rationale

Some algorithms have known hash collision weaknesses.

## Static exemptions

`DUO130` supports narrowly scoped, auditable exemptions only for the explicit
`file_bucketing` purpose. An exemption is a static literal in the checked file
assigned to `DLINT_DUO130_EXEMPTIONS`. Each entry must identify one existing
check result by file path, enclosing qualified function scope, function line
range, location-independent structural fingerprint, exact result line and
column, and an inclusive `valid_until` date in `YYYY-MM-DD` format.

The structural fingerprint is the SHA-256 digest of the function's normalized
AST representation, excluding source locations. It remains stable when the
function body and signature do not change, but changes when either is edited.
The recorded line range still rejects a moved function, and the ledger also
records an `approval_id` for the security review that authorized the call site.

Exemptions do not cross nested function boundaries. A same-named local
function or a function moved to another line cannot reuse an existing entry.
An active entry that does not match a current `DUO130` result fails the check,
so approvals cannot remain in effect after refactoring. Flake8 `ignore`,
`extend-ignore`, `select`, and `noqa` behavior remains unchanged.

```python
DLINT_DUO130_EXEMPTIONS = [
    {
        'approval_id': 'SEC-1234',
        'check_code': 'DUO130',
        'filename': 'storage/buckets.py',
        'function_fingerprint': '...',
        'function_start_line': 12,
        'function_end_line': 14,
        'lineno': 13,
        'col_offset': 11,
        'purpose': 'file_bucketing',
        'qualified_name': 'bucket_key',
        'valid_until': '2030-01-01',
    },
]
```

## Exceptions

* Compatibility with systems that can only use MD5 or SHA1 and are not under your control
