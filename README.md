## 01 Mach-O 尾页的签收凭据

地狱 · 软件保护与加壳 · Python, macholib

送检的通用 Mach-O 有两张签收单，一张只说“有签名”，另一张说“所有代码页核过”。请让 macholib 能只读核对第二张单子。沿各切片的 LC_CODE_SIGNATURE 找到嵌入的主、备 CodeDirectory，按各自算法、页大小和 codeLimit 从原始切片重算普通代码槽，支持 SHA-1 和 SHA-256 的连续分页目录。结果要能指回切片、目录和页的文件范围，尾页按实际长度算；碰到散页表、未知算法或缺掉一截的目录，保留其他目录的独立结论。拿一个双架构的小文件验收：交换切片的物理位置，核对结果应随架构走；只改尾页一个字节，应恰好指出覆盖它的失配槽。我们要的是页内容的复核凭据，界面即使看到全部吻合也不能宣称签署者可信。

## 02 从两份备份复核计划任务改名

困难 · 数字取证 · Python, python-registry

接手一份 Windows 备份时，交接单说其中两项计划任务只是改了名字。我想从只读材料复核这句话。用 python-registry 读取同一备份 SOFTWARE hive 里的 TaskCache，把 Tree 项的 Id、Tasks 下对应 GUID 的 Path，和单独交来的任务 XML 清单对起来。保留每一条关系的原始路径和证据位置，只有双向登记与同批文件能对应时才给出完整登记；XML 的 URI 存在时一并核对，缺省要和矛盾分开。另一次备份可拿来比较，但同名和复用 GUID 都不能单独证明改名。验收给两次小型备份：交换两个 Id、留下一个旧 XML，再把一个子目录标成未完整采集。我要看到哪些关联拆开了、哪份文件成了孤证，不能因为没交齐目录就把任务写成已删除。只分析归档材料，无需 Windows 服务。

## 03 追查多语言客户端残留的撤回告知

地狱 · 安全风控与治理策略 · Python, dnfile

某批客户端撤回了旧的凭据泄露处置说明，安全响应组要确认法语用户还会不会看到已撤回的文本。交付方只发来了主程序集和几份 satellite DLL。给 dnfile 做一个离线审查入口，输入交付文件、资源基名、要查的键，已撤回文本的 SHA-256 清单，以及发行方列出的文化回退顺序和中性资源位置；只读托管元数据和内嵌 .resources，不加载程序集。先按程序集身份、文化和版本匹配，再逐键回退，区分缺少整份交付物、已读全但没这个键、键存在却不是可审查的字符串。调用方会标出哪些文化目录已经完整盘点，没盘全的上层候选不能被跳过后盖章通过。用两个共享父文化的请求查同一包：其中一个在子文化找到，另一个要回到父文化；拿掉父目录的盘点凭据后，只让依赖它的结论转为待补件。对确实可达的文本按解码后的 UTF-8 字节核对撤回清单，命中时给出具体程序集、资源名和键，响应组要据此决定拦哪一包。

## 04 抓包里的主机日志怎样读回

困难 · 模糊测试（Fuzzing） · Python, python-pcapng

抓包里夹着一条主机审计事件。普通包能正常读，取证脚本却把二进制 MESSAGE 里的换行当成了另一条记录。请为 python-pcapng 的 FileScanner 补上 systemd Journal Export Block 的取证读取，并围绕它做一组可重放的结构化模糊测试。合法事件要保留同名字段出现的次序、原始字节范围和必需的实时时间戳；块尾对齐与值尾的零字节各有各的位置。测试从已知字段序列独立编码，交替放进大小端的节，比较读回的值和证物切片，再把二进制长度、终止符或时间字段单独破坏。外层块边界完整时，后端应能隔离该事件并接着读后面的报文；外层也不完整时只能停在最后一个有依据的位置。留下一个固定种子，让接案的人几秒内能重放差异，无需 systemd 服务。

## 05 找出带走临时许可的异步任务

地狱 · 漏洞利用与缓解 · Python, DLint

后台报表偶尔能读到本应在请求结束时收回的明文读取许可。我们把许可放在指定的 ContextVar 里，想让 DLint 在代码评审时挑出会把它带出作用域的任务。给现有 flake8 入口加一条可配置规则，按绑定对象追踪 set 返回的 token、reset 所在的各条退出路径，以及 asyncio.create_task 真正创建任务时继承的上下文。只构造协程随后才调度、显式传入空 Context、子任务在许可区间内已被等待结束，这三种都要分别处理。先限定到同一模块内能解析的绑定和辅助函数，对无法证明何时结束的任务给单独诊断。验收用普通的模拟读取函数：把调度移到 reset 前后、把等待从 try 移到只有正常出口才经过的位置，分别看现有插件给出的行号和原因。代码片段只供静态检查。

## 06 两处签收站交来的日志根

地狱 · 顺带涉及上下游链路 · Python, securesystemslib

两处归档站都交来了验签通过的制品日志根，但我们上周保存的签收根只有一个。请在 securesystemslib 的 Python 接收端加一个离线见证器：检查点用现有 DSSE 验签，载荷绑定日志身份、叶数和根；树按 RFC 6962 的 SHA-256 叶/内部节点定义。首次锚点由调用方显式固定，此后要分别验证旧树到新树的一致性证明，以及指定制品在新树的包含证明，两件都成立才出具签收。相同大小不同根、同根重投、旧的乱序包和无法证明扩展的较大树，需要留下可区分的处置结果。两个进程从同一锚点提交时，以实际落盘的锚点复核，写入中断后重新打开仍能说明最后信的是哪棵树。夹具用三叶扩成五叶，再给另一条同样有合法签名的五叶分支；复验旧收据时，请能指出分歧的两份原始检查点。

## 07 定位 Outlook 附件上的审批号

困难 · 数字取证 · Python, olefile

“审批号”出现在两份 Outlook .msg 里，调查员按 0x8000 开头的属性号做了关联。请基于 olefile 补一个供案件后端调用的 MSG 附件索引：读取消息的命名属性映射，把 GUID 与字符串名或数值名作为属性身份，并把附件的值定位到具体存储路径。遇到嵌入邮件按 MSG 的映射作用域处理，遇到作为普通二进制附件保存的另一份完整 MSG 则重新建立它自己的映射；允许限制递归深度并标出截止处。一个证物有短名、长名相同的两个附件也得分得开。拿两份最小复合文件演示同号异义、异号同义和一个缺失的映射项；我应当能从索引返回原始流重读每个被引用的值，并知道哪一条关联目前只有猜测。

## 08 验证 ELF 导出声明能否查到

地狱 · 二进制/固件逆向 · Python, pyelftools

供应商说固件里的共享库导出了指定版本的函数，证据是一行符号表输出。请给 pyelftools 做个静态复核接口，输入一份 ELF 和名称，可再指定 GNU 符号版本。分别说明动态符号表里有哪些候选，以及从该文件声明的 GNU、SysV 哈希索引走一遍，各自确实能找到谁；显式指定旧版本与按默认版本查询要分开。解析需要在去掉节头后仍能用 PT_DYNAMIC 和可定位的加载段工作。双索引不一致时保留各自的查找路径，缺少可靠上界就给未决。离线验收准备两个同名不同版本的符号：正常件、只改其中一张索引的副本、同内容无节头的副本。复核者应能据文件偏移和 dynsym 序号说明哪份声明站得住，整个过程不用运行目标文件。

## 09 盘位不明时可以交付哪些字节

地狱 · 数字取证 · Python, dissect.cstruct

有三块脱机盘的局部镜像，盘位标签掉了，交接单只留下两种可能布局。基于 dissect.cstruct 给取证后端做一个只读的 RAID5 区间读取器。调用方给出候选盘序、每条带的数据盘顺序与校验盘、块大小、已采集区间，还能给若干已知逻辑位置的结构字段作为独立锚点。先用确实采到的字节和 cstruct 解出的字段排除矛盾布局，一条带只缺一份时可按异或恢复。剩下多种布局，就逐段交付所有候选都能支持的相同字节，附物理来源和直接读取或推导的标记；空洞不能当零，两份都缺也不能猜。请用内存盘做一例：交换两个数据盘后所有校验仍然通过，首次只能读出部分请求；再补一处跨块锚点消除歧义。把其中一段采集区挖掉，同一读取应清楚标出新出现的缺口。

档案交接要换一批 Office 文件的保管口令，原签收单记的是 EncryptedPackage 流的摘要。给 msoffcrypto 的 OOXML 库入口增加口令轮换，范围限定为已知旧口令、只有一个 password key encryptor 的 Agile 文档。先用旧凭据和完整性信息验证现有材料，再让新口令封装同一份内容密钥；包内密文逐字节保留，公开返回值和错误里都不要带出密钥或口令。遇到证书收件人、多个口令槽、旧口令不对或完整性检查失败，调用方需要明确原因且既有目标文件可照常使用。验收会用旧库重新打开新文件，对照原包摘要并试新旧两把口令，还要模拟写到半途失败。档案员最终只需要一张能和原签收单勾稽的轮换回执。
