# dns_audit：基于 dpkt 的离线 DNS 问答核对

复盘场景：有人拿一份 DNS 抓包声称“两个名字一直指向同一组地址”。样本来自
多个采集点，其中一处同 txid 的请求并不是另一份回答的来源。本工具只用 dpkt
做**离线**解析，把保存下来的问答组合成**有限**的名称/地址主张，并完整保留
每一步的采集归属、匹配依据与声称的有效范围；没有看全的链和无法排除的多个
候选都原样保留，可复查。

## 核心原则

- **采集点隔离**：问答只在同一采集点内配对。txid 是 16 位易复用编号，
  跨采集点出现同号只登记为碰撞，绝不互相串证。
- **匹配依据留痕**：唯一配对必须同时满足同采集点、txid 相等、问题段一致、
  套接字五元组反向、回答时间不早于问题，且只有一个候选。
- **多候选不猜测**：同采集点内出现无法排除的多个候选问题时标记
  `ambiguous`，保留全部候选帧，不产生主张；孤立回答标记 `orphan_response`。
- **主张带范围**：每条主张记录观察窗（实际看到问答的时间）与按 TTL 的外推
  到期时间；TTL 外推不等于后续观测，截断回答（TC=1）会显式标注。
- **离线别名观察**：仅用抓包内的 CNAME/A/AAAA 记录按采集点构建别名图，
  链未看全（终点无地址记录、多目标、环路）时标为不完整并保留每跳证据。
- **同址核对受限**：只在同一采集点、同一观察窗内比较名称的地址集合，
  结论措辞限定为“观察窗内一致/不一致”，不外推到窗口外或其它采集点。

## 目录结构

- `dns_audit/model.py`：数据模型（报文、问答交换、主张、有效范围）。
- `dns_audit/reader.py`：pcap 离线读取，逐帧标注来源/采集点/帧号与解析异常。
- `dns_audit/matching.py`：按采集点隔离的问答配对与跨点 txid 碰撞清单。
- `dns_audit/claims.py`：从唯一配对中提取地址、别名、否定主张。
- `dns_audit/alias.py`：离线别名图、不完整链标注。
- `dns_audit/audit.py`：端到端聚合、同址核对、JSON 序列化。
- `dns_audit/cli.py`：命令行，输出 text 或 json 报告。
- `tests/`：内存 pcap 合成夹具与测试（含跨采集点同号陷阱）。

## 用法

```bash
python -m dns_audit \
  --capture edge_a=edge_a.pcap \
  --capture edge_b=edge_b.pcap \
  --report text
```

`--capture SITE=PATH` 可重复指定，把每个 pcap 显式绑定到采集点；
`--report json` 输出机器可读报告，`--output` 指定写入文件。

## 测试

```bash
python -m pytest
```

测试用 dpkt 的 pcap/Ethernet/IP/UDP 栈在内存中合成抓包。注意 dpkt 1.9.8 的
`DNS` 打包器会生成无效的压缩指针、无法被其自身解析器往返，因此夹具按
RFC 1035 手工编码 DNS wire 数据（真实抓包的标准压缩指针可正常解析）。
